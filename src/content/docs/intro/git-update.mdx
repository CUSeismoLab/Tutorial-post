CUSeismoLab Tutorial is built with [Astro](https://astro.build/) and [Starlight](https://starlight.astro.build/). Every tutorial is a plain MDX file in the [CUSeismoLab/Tutorial-post](https://github.com/CUSeismoLab/Tutorial-post) repository, so fixing a typo, improving an explanation, or adding a new chapter only takes a text editor and Git. Changes merged into the `main` branch are built and published to the website automatically by GitHub Actions.

## Quick edits on GitHub

For a small fix to a single page, you don't need to set anything up locally:

<Steps>

1. Open the page's file in the repository, e.g. `src/content/docs/unix/index.mdx`.

2. Click the pencil icon (**Edit this file**). If you don't have write access, GitHub will create a fork for you.

3. Make your change, then choose **Commit changes** and open a pull request.

</Steps>

## Edit and preview locally

For larger changes, work on a local copy so you can preview the website before publishing.

### Set up

You need [Git](https://git-scm.com/) and [Node.js](https://nodejs.org/) 24 (or 22.23.4 or newer). If you use [nvm](https://github.com/nvm-sh/nvm), `nvm use` picks the right version from `.nvmrc`.

<Steps>

1. Clone the repository (or your fork of it) and enter the directory:

   ```sh
   git clone https://github.com/CUSeismoLab/Tutorial-post.git
   cd Tutorial-post
   ```

2. Install the dependencies:

   ```sh
   npm ci
   ```

3. Start the development server:

   ```sh
   npm run dev
   ```

   Open the address printed in the terminal (normally `http://localhost:4321`). The page reloads automatically whenever you save a file.

</Steps>

### Where things live

| Path | Content |
| --- | --- |
| `src/content/docs/<chapter>/index.mdx` | The text of each tutorial chapter |
| `public/media/<chapter>/` | Images, notebooks, scripts, data, and other downloadable files |
| `astro.config.mjs` | The sidebar and site settings |
| `src/components/CourseCatalog.astro` | The course list on the homepage |

### Writing content

Chapters are written in Markdown, with a few extras:

- Fenced code blocks (```` ```python ````) are syntax-highlighted.
- Use `$...$` for inline equations and `$$...$$` for display equations (KaTeX).
- Use `:::note`, `:::tip`, and `:::caution` for callout boxes.
- Link to other chapters as `/chapter/` and to files as `/media/chapter/file.ext`. The deployment path is added automatically.

Keep the `slug` in each chapter's front matter unchanged, so that existing links keep working.

### Adding a new chapter

<Steps>

1. Create `src/content/docs/<chapter>/index.mdx` with a front matter block:

   ```mdx
   ---
   title: "My new tutorial"
   slug: my_new_tutorial
   ---
   ```

2. Put its images and files in `public/media/<chapter>/`.

3. Add the chapter to the sidebar in `astro.config.mjs`, under the appropriate level.

4. Add it to the course list on the homepage in `src/components/CourseCatalog.astro`.

</Steps>

### Check before you push

Run these commands before pushing to catch broken pages and links:

```sh
npm run check
npm run build
npm run verify
```

`npm run preview` serves the production build, including full-text search, which isn't available in the development server.

## Submit your changes

<Steps>

1. Create a branch for your work:

   ```sh
   git switch -c fix-unix-typo
   ```

2. Stage and commit your changes:

   ```sh
   git add <modified files/folders>
   git commit -m "Fix typo in the Unix chapter"
   ```

3. Push the branch:

   ```sh
   git push -u origin fix-unix-typo
   ```

4. Open a pull request on GitHub. Once it is reviewed and merged into `main`, the website updates automatically within a few minutes.

</Steps>
